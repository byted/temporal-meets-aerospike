    Ordered task queues, emulated by bucketing

    Cassandra hands Temporal one clustered partition per shard and answers “tasks in [min, max), ascending” with a single range scan. Aerospike has no clustering key and no ordered scan — so the clustering key becomes a map key, and the partition becomes a run of bucketed records.

    One Aerospike record per bucket. Every bucket holds a K-ordered map in bin t, and the server returns that map's entries in key order. Bucket numbers are monotonic in the sort key, so a range read walks the buckets in order and gets a globally ordered stream out the far end. That is the whole trick.

    Visibility is unchanged by the switch — only the operational store is replaced.
